# Design Principles

## 1. Clarity before decoration

Every element must support comprehension, action, orientation, or feedback. Remove decoration that does not do one of those jobs.

## 2. Quiet confidence

Use neutral surfaces, deliberate spacing, solid accents, and crisp hierarchy. The product should feel mature and dependable rather than futuristic or promotional.

## 3. One system, many contexts

Components should be recognizable across screens. Variation comes from composition and content, not from inventing a new visual treatment for each feature.

## 4. Semantic meaning over appearance

Use tokens by purpose (`text.primary`, `border.strong`, `status.danger`) rather than by color name. This keeps themes, accessibility, and future brand changes manageable.

## 5. Accessible by default

Keyboard access, focus visibility, readable contrast, target sizing, reduced motion, and clear errors are baseline requirements, not polish.

## 6. Responsive without surprise

Preserve task priority as space changes. Reflow, stack, collapse, or simplify content intentionally; do not merely shrink desktop layouts.

## 7. Honest feedback

Show system status, validation, loading, empty, success, and failure states in plain language. Do not use animation or color as the only feedback channel.

## 8. Restraint is a feature

Avoid gradients, glows, neon, glassmorphism, oversized display text, excessive rounded cards, and decorative illustrations unless the project brief gives a clear functional reason.
